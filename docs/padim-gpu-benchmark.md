# PaDiM GPU 性能与验证报告

测量日期：2026-10-19。实现与开关见 [PaDiM GPU 模式设计](padim-gpu.md)。
本机单张图像端到端推理从 CPU 的 54.90 ms 降到 3.90 ms；
与同一 TensorRT engine 加 CPU 计算阶段相比，新增 CUDA 计算链路约快 4.10×。
以下结果针对所列硬件和规模，不代表所有模型或 batch 的固定收益。

## 环境和方法

- Windows，Intel Core i5-13400F（10 核、16 逻辑处理器），NVIDIA RTX 5070 Ti 16 GB。
- NVIDIA 驱动 616.64，CUDA Toolkit 13.2.78，计算架构 120。
- MSVC 19.51.36257，Release / Ninja，OpenCV 4.13，TensorRT 10.16.1.11。
- 启用 ONNX Runtime、TensorRT、CUDA compute，关闭 GPU Faiss；PaDiM 没有 Faiss 检索阶段。
- 阶段基准预热 2 次后取 7 次中位数；拟合两项各测量 5 次。GPU 调用同步完成后停止计时。
- 测量时不并行运行编译、其他测试或 GPU 检查；未锁定 GPU 频率或 CPU 亲和性，使用库默认线程配置。
- CPU 基线使用现有特征/adapter/拟合实现，单独距离项使用测试内等价的 double 累加参考循环，未额外优化 CPU SIMD/GEMM。
- 性能数据是一次基准运行中的重复测量中位数，没有给出跨进程置信区间。

## 实际网络端到端

使用项目自带 `deployment/model/wide_resnet50_2_patchcore.onnx` 作为 PaDiM 特征网络，
输入一张合成 224×224 BGR 图像。提取 layer2（512×28×28）和 layer3（1024×14×14），
选择 100 个通道，在 28×28 网格使用合成均值和稠密正定精度矩阵，Gaussian sigma=4。
该导出模型还保留原有分类输出，本次没有裁剪网络。

CPU 模式使用 ONNX Runtime；两种 TensorRT 模式共用同一个新建的临时 engine。
模型加载、统计参数上传和 engine 构建不计入稳态耗时。
每种模式预热 3 次，测量 9 次；按总耗时排序，取中位样本及该样本的阶段耗时。

单位为 ms。

| 模式 | 总耗时 | 预处理 | 网络及传输 | PaDiM adapter | 最终后处理 |
| --- | ---: | ---: | ---: | ---: | ---: |
| CPU | 54.8980 | 0.3848 | 40.8996 | 13.5600 | 0.0520 |
| TensorRT + CPU 计算阶段 | 15.9967 | 0.4172 | 4.0061 | 11.5131 | 0.0589 |
| TensorRT + CUDA 计算阶段 | 3.9001 | 0.1407 | 3.0978 | 0.5973 | 0.0638 |

新增 CUDA 路径相对 TensorRT + CPU 阶段快 **4.10×**，总延迟减少 **75.62%**；
PaDiM adapter 从 11.5131 ms 降到 0.5973 ms，约 **19.28×**。
相对纯 CPU 模式快 **14.08×**，其中包含 ONNX Runtime → TensorRT 的网络收益，不能全部归因于新增算子。
网络阶段的下降也包含网络特征不再下载到主机的收益。

CUDA 模式的 `compute_provider=2`、`device_tensor_path=1`，其他两种模式分别为 1 和 0。
同一 TensorRT engine 下，CPU/CUDA 计算阶段之间 raw score 绝对误差为 **1.90735e-6**，
raw anomaly map 最大绝对误差为 **7.62939e-6**（检查阈值均为 1e-3）。
这里的数值比较没有将 ORT 与 TensorRT 的网络数值差异混入新增计算阶段误差。

图像和统计参数均为合成数据；本次验证计算一致性和耗时，没有测量真实异常数据集的 AUROC 或检测精度。
原始数据：[推理 CSV](benchmarks/padim-gpu-inference.csv)。

## 各阶段和拟合对照

单位为 ms，加速比为 CPU / CUDA。特征选择输入为 batch=4 的 512×28×28 与 1024×14×14 两层，
输出选定的 100 个通道。距离和 adapter 均使用每个位置独立的完整精度矩阵。

| 阶段 | 规模/数据边界 | CPU | CUDA | 加速比 |
| --- | --- | ---: | ---: | ---: | ---: |
| 特征选择 | 主机输入及输出 | 28.5186 | 1.7866 | 15.96× |
| 特征选择 | 网络特征已在显存 | 32.9470 | 0.0624 | 528.00× |
| 马氏距离 | 4×784×100，主机 patch 及输出 | 19.3124 | 1.3346 | 14.47× |
| 马氏距离 | 4×784×100，显存常驻 patch 及输出 | 18.1735 | 1.1625 | 15.63× |
| PaDiM adapter | 主机特征 → 4 张 224×224 主机异常图 | 46.2563 | 3.7482 | 12.34× |
| 拟合统计更新 | 每批 16×784×100，GPU 输入常驻 | 91.2709 | 2.1422 | 42.61× |
| 拟合 finalize | 784 个 100×100 矩阵，含文件写入 | 300.4830 | 38.6755 | 7.77× |

这些阶段使用不同输入边界，不能直接相加推算端到端耗时：

- 特征选择主机对照包含 GPU 输入上传、输出下载和临时分配。CPU 会先聚合完整特征再选通道；GPU 融合插值与选择，只计算所需通道，因此收益也包含减少无用计算和中间张量。
- 显存特征选择比较 CPU 下载特征后聚合与 GPU 直接处理、输出留在显存两条路径。约 528× 包含消除下载及完整通道聚合的收益，不能解释为同一 kernel 的纯计算加速比。
- 两项距离测试均提前上传均值和精度矩阵。主机项计入 patch 上传与距离下载；显存项排除这些传输，与 CPU 主机计算作路径对照。
- adapter 对照在两端均使用同一组主机特征和主机最终异常图，包含 GPU 的输入上传与输出下载，覆盖实际 adapter 实现。
- 统计更新使用相同 NCHW embedding，CPU 输入在主机，GPU 输入提前上传。统计缓冲分配被预热排除；每次增加 16 个样本，2 次预热加 5 次测量后各累计 112 个样本。不是图像到训练产物的全流程加速比。
- finalize 使用上述相同样本统计，GPU 包含分块求解、产物下载及文件写入；CPU 同样包含文件写入。

原始数据：[阶段 CSV](benchmarks/padim-gpu-stages.csv)。

## 正确性与兼容验证

- CUDA 构建完整 CTest：**26/26 通过**，包含 12 项既有 PatchCore CUDA 测试和 6 项新增 PaDiM CUDA 测试。
- 纯 CPU 构建 CTest：**7/7 通过**；主库依赖检查没有 CUDA DLL。
- Compute Sanitizer memcheck：特征选择、马氏距离、统计、拟合 4 项各 **0 errors**。此项没有覆盖完整 TensorRT 端到端运行。
- 特征选择覆盖通道乱序、非整数缩放、单像素、主机/设备输入、越界和重复通道、错误形状及截断缓冲。
- 马氏距离覆盖 D=1、5、33、100、550 的稠密非对角正定矩阵；按 `2e-6 + 2e-6 * abs(CPU)` 容限比较，并验证非有限值和非法负二次型。
- double 统计与 CPU 参考比较；拟合产物按 `5e-6 + 3e-6 * abs(CPU)` 容限比较，检查非正定协方差、非法批次、清空重训。
- 训练覆盖显存常驻与强制分块、CPU↔GPU checkpoint、常驻↔分块恢复，保持现有 ANPADIM v1 产物及 checkpoint 格式。
- adapter 覆盖 sigma=0、1.3、4，验证分数确为最终平滑异常图最大值；session/C ABI 覆盖 AUTO/CPU/CUDA、不可用设备、显式模式拒绝、拟合及执行信息。
- sigma=512 的 CPU 合法配置在加载阶段验证 AUTO 回退及显式 CUDA 拒绝。

测试源码和基准入口保留在本地工作区，复现命令见 [设计文档](padim-gpu.md#使用与复现)。

## 收益边界和后续方向

当前推荐的默认路径是 TensorRT 显存输出 → 选定通道融合 → 马氏距离 → 异常图 CUDA 处理，
只下载需要返回的最终异常图。拟合统计能常驻显存时收益明显，分块求解也缩短了 D=100 的 finalize。

大维度的 `L*D*D` 状态仍是显存主要开销。超出默认 512 MiB 统计预算后的主机分块路径已验证正确性，
但本次没有测量其性能，也没有测量 D=550 拟合性能，不能据此保证更大配置同样加速。
小 batch、小网格也可能因分配、同步和传输开销降低收益。

若继续优化，先用实际生产模型测量常驻显存和分块路径，再评估跨插件 stream/event、
临时缓冲复用和双缓冲传输；这些改进尚未实现。当前保留同步合约以及 double 统计/累加，
没有为了速度默认降低数值精度。
